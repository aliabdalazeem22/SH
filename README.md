# SwiftShare — مشاركة ملفات مباشرة بين أجهزة أندرويد

تطبيق أندرويد أصلي (Kotlin + Jetpack Compose) لنقل الملفات مباشرة من جهاز إلى جهاز قريب، دون حساب، ودون سحابة، ودون إنترنت، ودون بيانات جوّال.

- **اسم الحزمة:** `com.example.swiftshare`
- **اللغة الافتراضية:** العربية (واجهة RTL)، مع الإنجليزية في `values-en`
- **أقل إصدار مدعوم:** Android 7.0 (API 24)
- **هدف البناء:** Android 15 (API 35)
- **محرّك النقل:** Google Nearby Connections 19.1.0 باستراتيجية `P2P_STAR` (اكتشاف عبر Bluetooth، بيانات عبر Wi-Fi محلي)

## الميزات

- **نقل مباشر بين جهازين:** لا يوجد خادم وسيط، ولا رفع إلى سحابة، ولا استخدام للإنترنت أو بيانات الجوّال. التطبيق **لا يطلب إذن `INTERNET`** أصلًا، لذا لا يمكنه التحويل إلى الشبكة حتى بالخطأ.
- **اختيار متعدد للملفات:** عبر منتقي النظام (SAF) لأي نوع ملفات، بما في ذلك APK. لا حاجة لأي إذن تخزين، والوصول ممنوح لكل ملف على حدة.
- **بث الملفات من القرص:** يُمرَّر الملف إلى Nearby Connections كـ `ParcelFileDescriptor` ويُبثّ دون تحميل الملف كاملًا في الذاكرة.
- **بروتوكول بتأكيد ثنائي:** المرسل لا يعلن نجاح الملف إلا بعد أن يتحقق المستقبل من كتابته على القرص ويرسل `DONE`.
- **الاستقبال الآمن:**
  - الكتابة أولًا في ملف مؤقت داخل `cacheDir`.
  - التحقق من الحجم بعد اكتمال النقل.
  - عند التطابق فقط يُنقل الملف إلى المجلد النهائي باسم فريد.
  - لا يظهر ملف جزئي أبدًا كملف مكتمل، وعند فشل التحقق يُرسل `FAIL` ويُحذف المؤقت.
- **أسماء فريدة:** عند وجود اسم مطابق يُضاف ` (1)`، ` (2)`، إلخ.
- **حماية من المسارات الخبيثة:** تُنظَّف أسماء الملفات الواردة من أي أجزاء مسار أو `..` أو محارف تحكم (`FileNaming`).
- **التقدم:** اسم الملف الحالي، رقم الملف من الإجمالي، الحجم المنقول/الكلي، السرعة الفعلية (MB/s)، والوقت المتبقي التقديري.
- **الإلغاء وإعادة المحاولة:** إلغاء آمن من شاشة النقل أو الإشعار، وإعادة محاولة من شاشة النتيجة.
- **تأكيد على الطرفين:** المستقبل يرى اسم المرسل ورمز التحقق ويجب أن يقبل الاتصال قبل نقل أي ملف.
- **سجل نقل محلي:** JSON صغير داخل التطبيق يحتوي الاسم والحجم والاتجاه والسرعة والحالة والوقت فقط — **لا يحتوي محتوى الملفات**. يُحتفظ بآخر 500 عملية كحد أقصى.
- **قياس سرعة حقيقي:** إرسال ملف اختبار فعلي عبر مسار النقل نفسه، مع عرض الحجم والزمن والنتيجة المقاسة. لا توجد أرقام مُختلقة.
- **واجهات كاملة:** الرئيسية، اختيار الملفات، الاكتشاف، طلب الاستقبال، النقل، الاكتمال/الفشل/الإلغاء، السجل، الإعدادات، وقياس السرعة، مع حالات تحميل/فراغ/نجاح/خطأ.
- **تصميم أصلي:** ألوان وخطوط وهوية بصرية خاصة بـ SwiftShare، وضع داكن، دعم RTL، وأحجام لمس مناسبة.

- **الواجهة (UI):** Compose فقط، بلا منطق نقل.

## كيف يعمل النقل

الاستراتيجية `P2P_STAR`، وملف واحد في المرة (stop-and-wait) لضمان ترتيب واضح وتأكيد كتابة كل ملف:

```
المرسل  → المستقبل : BYTES  {"i":index,"t":total,"n":name,"s":size}
المستقبل → المرسل  : BYTES  "OK:index"        (المستقبل جاهز)
المرسل  → المستقبل : FILE   (بث من ParcelFileDescriptor)
المستقبل            : كتابة مؤقتة → تحقق الحجم → نقل لاسم فريد
المستقبل → المرسل  : BYTES  "DONE:index"      (تم التحقق على القرص)
المرسل  → المستقبل : BYTES  "END"              (بعد آخر ملف)
```

- عند عدم تطابق الحجم يرسل المستقبل `FAIL:index` ويحذف المؤقت.
- الاتصال يتم عبر `requestConnection` من المرسل، ويجب على المستقبل استدعاء `acceptConnection` صراحةً بعد موافقة المستخدم.
- رمز التحقق (`authenticationDigits`) يُعرض على الطرفين لمقارنته بصريًا.
- تُستخدم `stopAdvertising()` / `stopDiscovery()` / `stopAllEndpoints()` عند الإلغاء أو مغادرة الشاشة.

## الأذونات

التطبيق يطلب الحد الأدنى المطلوب من Nearby Connections فقط، ولا يطلب تخزينًا ولا إنترنت:

| النطاق | الأذونات |
|---|---|
| API 31+ | `BLUETOOTH_SCAN`، `BLUETOOTH_CONNECT`، `BLUETOOTH_ADVERTISE` (وقت التشغيل) |
| API 33+ | `NEARBY_WIFI_DEVICES` (وقت التشغيل) |
| API 29–30 | `ACCESS_FINE_LOCATION` (وقت التشغيل) |
| API 24–28 | `ACCESS_COARSE_LOCATION` (وقت التشغيل) |
| عادية | `ACCESS_WIFI_STATE`، `CHANGE_WIFI_STATE` (حتى API 32)، `BLUETOOTH`/`BLUETOOTH_ADMIN` (حتى API 30) |

**غير مطلوب:** `INTERNET`، `READ_EXTERNAL_STORAGE`، `WRITE_EXTERNAL_STORAGE`، `MANAGE_EXTERNAL_STORAGE`، `REQUEST_INSTALL_PACKAGES`.

> لا يوجد إذن إنترنت في البيان إطلاقًا. هذا خيار تصميمي يمنع أي نقل سحابي أو عبر بيانات الجوّال.

ملاحظة دقة: قد تُضيف مكتبات Google Play Services عند الدمج إذن `ACCESS_NETWORK_STATE` (قراءة حالة الاتصال فقط، ولا يمنح وصولًا للإنترنت) وإذنًا داخليًا لمستقبلات AndroidX غير المصدَّرة. إذن `INTERNET` نفسه غير موجود في APK النهائي.

الملفات المستلمة تُكتب في مجلد خاص بالتطبيق:

```
Android/data/com.example.swiftshare/files/Download/SwiftShare
```

ويُعرض المسار الفعلي في شاشة الإعدادات.

## البناء والتشغيل

### المتطلبات

- JDK 17
- Android SDK Platform 35 و Build-Tools 35.0.0
- Android Studio حديث (Ladybug أو أحدث) أو Gradle Wrapper المرفق (Gradle 8.9)

### أوامر

```bash
cd SwiftShare

# بناء APK للتطوير
./gradlew :app:assembleDebug

# اختبارات الوحدة
./gradlew :app:testDebugUnitTest

# فحص Lint
./gradlew :app:lintDebug
```

الناتج:

```
app/build/outputs/apk/debug/app-debug.apk
```

ثم:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

### ملاحظة خاصة ببيئات ARM64 Linux

إذا كان SDK يحتوي `aapt2` مخصصًا لـ x86_64 على مضيف ARM64، فقد يفشل البناء برسالة تنفيذ `aapt2`. الحل المؤقت في هذه البيئة:

```bash
./gradlew :app:assembleDebug \
  -Pandroid.aapt2FromMavenOverride=/path/to/working/aapt2
```

هذا الخيار **بيئي فقط** ولا يُضاف إلى `gradle.properties` ولا يُرفع مع المشروع. على Windows/macOS/x86_64 Linux لا تحتاجه.

### فتح المشروع في Android Studio

1. `File → Open` واختر مجلد `SwiftShare`.
2. انتظر مزامنة Gradle.
3. اختر جهازًا/محاكيًا وشغّل `app`.

> المحاكي لا يدعم Nearby Connections بشكل موثوق. استخدم جهازين حقيقيين للاختبار الفعلي.

تفصيل اختبارات الوحدة:

- `FileNamingTest` — 9 اختبارات: الأسماء العادية، إزالة المسارات، منع `..`، محارف التحكم، الأسماء الطويلة مع الامتداد، الأسماء الفريدة مع/بدون امتداد، وتنظيف الاسم قبل الكتابة.

**لم يُجرَّ اختبار على جهاز حقيقي في هذه البيئة** لعدم توفر جهازين. النتائج أعلاه تخص البناء والاختبارات الآلية وLint فقط. يلزم تنفيذ الاختبار اليدوي أدناه قبل أي ادعاء عن الأداء أو السلوك الفعلي.

### تحذيرات Lint المتبقية (غير مُعطِّلة)

- `UnusedResources`: نصوص/موارد محجوزة لميزات مستقبلية أو قديمة.
- `GradleDependency`: توجد إصدارات أحدث من بعض المكتبات.
- `UsableSpace`: يمكن استخدام `StorageManager.getAllocatableBytes` لتقدير أدق للمساحة (التحقق الحالي يمنع الكتابة عند نقص المساحة الظاهرة).
- `UnusedAttribute`: خصائص بيان خاصة بإصدارات أحدث من `minSdk` (تُتجاهل تلقائيًا على الإصدارات الأقدم).
- `PluralsCandidate`: صيغة `%d ملف`؛ يمكن تحويلها إلى `plurals` لاحقًا.

## اختبار يدوي على جهازين

يتطلب **جهازين حقيقيين** يعملان بنظام Android 7.0+ مع خدمات Google Play محدثة، والتطبيق مثبت على كليهما.

### أ. نقل ملفات (الاختبار الأساسي)

1. على **الجهاز ب (المستقبل):** افتح التطبيق → `استقبال` → امنح الأذونات → ستظهر شاشة «اجعل جهازك مرئيًا».
2. على **الجهاز أ (المرسل):** افتح التطبيق → `إرسال` → اختر ملفًا أو أكثر (جرّب صورة، PDF، وملفًا كبيرًا > 100 MB).
3. اضغط `البحث عن الأجهزة القريبة`، ثم اضغط على اسم الجهاز ب.
4. تحقق من ظهور **رمز التحقق نفسه** على الجهازين.
5. على الجهاز ب اضغط `قبول`.
6. راقب على الجهازين: اسم الملف، رقم الملف، الحجم، السرعة (MB/s)، والوقت المتبقي.
7. بعد الاكتمال تحقق من:
   - ظهور شاشة «اكتمل النقل» على الطرفين.
   - وجود الملفات في `Android/data/com.example.swiftshare/files/Download/SwiftShare` على الجهاز ب.
   - تطابق حجم/فتح الملفات.
   - ظهور سجلين (إرسال واستقبال) في شاشة السجل.

### ب. الأسماء المكررة

أرسل الملف نفسه مرتين. يجب أن يظهر الملف الثاني باسم مثل `photo (1).jpg` دون استبدال الأول.

### ج. الإلغاء والفشل

1. ابدأ نقل ملف كبير ثم اضغط `إلغاء` على المرسل. يجب ألا يظهر أي ملف جزئي في المجلد النهائي، وأن تظهر شاشة الإلغاء على الطرفين.
2. أعد المحاولة عبر `إعادة المحاولة`.
3. أثناء نقل، أغلق Wi-Fi على أحد الجهازين. يجب أن يظهر فشل واضح، وألا يُعرض ملف جزئي كاملًا.
4. دوّر أحد الجهازين أثناء النقل: يجب أن يستمر النقل بفضل `TransferViewModel`.

### د. الأذونات والإصدارات

- جرّب رفض الأذونات ثم منحها من الإعدادات، وتأكد من تحديث الواجهة فورًا.
- اختبر على إصدار Android 12+ (أذونات Bluetooth) وإصدار أقدم (إذن الموقع) إن توفر.

### هـ. استقبال APK

أرسل ملف APK عبر منتقي الملفات. يجب أن يُستقبل كملف عادي فقط، **دون أي تثبيت تلقائي** ودون طلب إذن تثبيت.

## وضع قياس السرعة (Benchmark)

### كيف يعمل

- يولد المرسل ملف اختبار عشوائيًا بالحجم المختار (10/25/50/100 MB) في `cacheDir`.
- يُرسله عبر **مسار النقل الحقيقي نفسه** (نفس البروتوكول والتحقق وكتابة المستقبل على القرص).
- يبدأ التوقيت قبل إرسال الترويسة وينتهي بعد استلام `DONE` من المستقبل.
- النتيجة = حجم الملف ÷ الزمن المنقضي، وتُعرض بالـ MB/s مع الحجم والزمن.
- الملف التجريبي يُحفظ على المستقبل باسم `swiftshare_benchmark.bin` (وقد يصبح `swiftshare_benchmark (1).bin` عند التكرار).

### خطوات القياس

1. وصّل الجهازين عبر شاشة `قياس السرعة` → `البحث عن جهاز استقبال` (دور المرسل).
2. على المستقبل، افتح `استقبال` واقبل الاتصال.
3. بعد الاتصال اختر حجم الملف التجريبي واضغط `بدء القياس`.
4. انتظر النتيجة. تحقق يدويًا: `الحجم (MB) ÷ الزمن (ثانية)` يجب أن يساوي تقريبًا الرقم المعروض.
5. كرّر القياس 3 مرات وسجّل التباين. لا تُنشر نتيجة واحدة كضمان.

> لا توجد أي أرقام سرعة مضمّنة في الكود. إن تعذّر القياس تُعرض رسالة فشل، ولا تُختلق نتيجة.

## الحدود والقيود

- **لا يوجد اختبار على أجهزة حقيقية في هذه البيئة.** البناء والاختبارات الآلية وLint فقط ما تم التحقق منه فعليًا.
- **خدمات Google Play مطلوبة** لتوفير Nearby Connections. الأجهزة بلا GMS (بعض أجهزة Huawei القديمة/الحديثة) غير مدعومة في هذا الإصدار.
- **يجب تثبيت التطبيق على الجهازين**؛ لا يوجد تطبيق ويب أو مشاركة رابط.
- **المحاكي غير مدعوم عمليًا** لاختبار Nearby.
- **مجلد الاستلام خاص بالتطبيق** (`Android/data/...`). على Android 11+ قد يقيّد مدير الملفات الوصول إليه؛ يمكن استخدام `adb pull` أو إضافة تصدير/مشاركة عبر MediaStore لاحقًا. لا توجد حاليًا واجهة «فتح/مشاركة» للملف المستلم.
- **لا نقل في الخلفية:** لا توجد خدمة أمامية؛ إذا أُغلق التطبيق أو قُتل بقوة فقد ينقطع النقل. تدوير الشاشة مدعوم.
- **ملف واحد في المرة** وبلا استئناف بعد الانقطاع؛ إعادة المحاولة تبدأ من جديد.
- **لا دعم QR أو رمز اتصال قصير** في هذا الإصدار؛ يُستخدم رمز تحقق Nearby فقط.
- **لا تشفير من طبقة التطبيق:** يعتمد الأمان على قناة Nearby Connections الموثّقة/المشفّرة حيث تتوفر، مع مقارنة رمز التحقق بصريًا. لا تنقل بيانات حساسة دون التحقق من الرمز.
- **APK:** يُشارك كملف عبر المنتقي فقط، ولا يُثبَّت تلقائيًا.
- **اللغة:** تتبع لغة النظام؛ العربية افتراضية والإنجليزية متاحة. لا يوجد مبدّل لغة داخل التطبيق.
- **السجل محلي فقط** ويُمسح من الإعدادات/السجل؛ لا مزامنة سحابية.
- **لا إذن إنترنت** يعني أيضًا تعذّر أي ميزة مستقبلية تحتاج شبكة (وهذا مقصود).

## إخلاء مسؤولية بشأن السرعة

السرعة الفعلية تعتمد على:

- نوع Wi-Fi والتردد (2.4/5 GHz) وجودة الراوتر/نقطة الاتصال.
- المسافة والعوائق المادية والتشويش.
- سرعة قراءة/كتابة التخزين على الجهازين.
- حرارة الجهاز وتوفير الطاقة وخلفيات النظام.
- إصدار Android وتنفيذ الشركة المصنعة.

الأرقام المعروضة قياسات فعلية لعمليات نُفِّذت، وليست وعودًا أو حدودًا دنيا. لا توجد أي سرعة مضمونة. استخدم وضع القياس في بيئتك للحصول على تقدير واقعي.

## البناء على GitHub (لإنشاء APK تلقائيًا)

المشروع متوافق مع GitHub Actions. ملف سير العمل موجود في:

```
.github/workflows/android-apk.yml
```

عند رفع المشروع إلى GitHub (أو التشغيل اليدوي `workflow_dispatch`):

1. تُثبَّت بيئة JDK 17 وAndroid SDK 35 على `ubuntu-latest`.
2. تُشغَّل اختبارات الوحدة وLint.
3. يُبنى `app-debug.apk`.
4. يُرفع كـ Artifact باسم `SwiftShare-debug-apk` (يمكن تنزيله من صفحة الـ Actions).

> ملاحظة: APK الناتج من الـ workflow هو Debug. للنشر على المتجر يلزم توقيع Release وإدارة المفاتيح بأمان (خارج المستودع).

للاطلاع على الأوامر الكاملة المستخدمة في البناء/التحقق/التغليف، راجع `docs/BUILD_AND_COMMANDS.md`.

## ملاحظات للنشر على GitHub

- الملف المضغوط `SwiftShare-Android-GitHub.zip` يحتوي المشروع فقط، **بدون** `.git` أو `.gradle` أو `build` أو `local.properties` أو APK أو مفاتيح توقيع.
- فك الضغط ثم:
  ```bash
  cd SwiftShare
  git init
  git add .
  git commit -m "Initial SwiftShare Android app"
  git branch -M main
  git remote add origin https://github.com/<user>/<repo>.git
  git push -u origin main
  ```
- لا ترفع `local.properties` أو أي ملفات توقيع. ملف `.gitignore` جاهز لذلك.
